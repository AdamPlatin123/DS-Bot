# DS Bot 的愿景

[English](vision.md) | 中文

本文写 DS Bot 要做成什么、为什么这样做，以及不做什么。功能怎么用，见 [README](../README.zh.md)；已定的具体设计，见 [docs/plans/](plans/)；怎么参与开发，见 [CONTRIBUTING](../CONTRIBUTING.zh.md)。

## DS Bot 是什么

DS Bot 是一支长期在线的 Bot 团队，基于 [DeepSeek Harness](https://github.com/deepseek-ai/deepseek-harness)（DSH）构建，开源，使用 Apache 2.0 许可。用户不是和一个助手聊天，而是带一支有分工的团队：一个或几个 Main Bot 负责组织，其他 Bot 各做各的事，互相沟通，用户随时能看到谁在做什么。

## 两种形态

| 形态 | 是什么 |
|---|---|
| `ds-bot` 插件 | 标准的 DSH 插件，装进 DSH Desktop 或 DSH Web 使用。Bot 的全部功能都在这里 |
| DS Bot 桌面应用 | 一打开就是 DS Bot。自带锁定版本的 DSH、自己的 profile 和数据目录，能导入用户在 DSH 里已有的团队，也能安装与 DSH 兼容的插件，逐步形成 DS Bot 自己的插件生态。插件仍然可以单独用 |

两种形态用的是同一份 `ds-bot` 插件。桌面应用的意义在于：DS Bot 自己掌握 profile 和界面，不再受 DSH 通用界面和全局配置的限制（见 [DSH 让步总账](plans/2026-10-13-dsh-concessions.md)）。

## 十条核心要求

1. **基于 DSH 构建。** 每个 Bot 都是一个 DSH Session，走 DSH 正常的 agent 循环、工具和模型路由。按 DSH 的插件规范来做，只用 DSH 有文档的接口，不修改 DSH，也不另造一套 agent 运行时。
2. **团队协作优先。** 重点是多个 Bot 一起工作，而不是一个 Bot。Bot 之间能互发消息、共用群聊。Main Bot 权限最高：能创建、修改、删除其他 Bot，可以有多个 Main Bot；普通 Bot 不授予这些权限。
3. **分工明确。** 每个 Bot 有自己的角色，团队里不应该是一群做同样事情的 Bot。
4. **界面精致，动效讲究。** 动效流畅、有因果：状态变化有过渡，操作有反馈，不为动而动。
5. **独立运行，互相可见。** 每个 Bot 单独工作，互不打扰；需要时能知道别的 Bot 在做什么。
6. **一个 Bot，一条连续的对话。** 用户看到的是一条连续的聊天。上下文快满时换到新的一段（新的 DSH Session），旧内容进索引、可以搜索，而不是一遍遍压缩把细节丢掉。
7. **主动的记忆。** Bot 有记忆系统，并且会主动去查，不只靠被动注入。
8. **可靠。** 思路对齐、做事有依据、目标有约束、结果可验证。Bot 拿不准时去查、去问，而不是猜。
9. **可定制。** 用户能定制每个 Bot：名字、角色标签、指令、模型、形象；以后扩展到系统提示词，乃至每个 Bot 用哪套 harness。
10. **能接入其他本地 Agent。** 以后可以把本机的其他 Agent（例如通过命令行）接进团队。

## 取舍原则

- **Bot 的正确行为优先。** DSH 某些模式或限制和 Bot 不兼容时，不为了兼容无限增加复杂度。不得不让步的地方，记进 [DSH 让步总账](plans/2026-10-13-dsh-concessions.md)，等桌面应用掌握 profile 后清理。
- **数据留在用户自己的电脑上。** 团队、聊天、记忆都存在本机的 DSH 数据目录里。
- **只用原创素材。** 代码、文字、图标、图形都不从其他产品复制。
- **能验证才算完成。** 行为要有测试覆盖，界面改动要实际看过。

## 不做什么

- 不修改 DSH，不依赖 DSH 安装目录里的内部文件。
- 不另造 agent 运行时，不绕开 DSH 的工具和权限。
- 不做云端托管的团队：DS Bot 跑在用户自己的 DSH 里。
