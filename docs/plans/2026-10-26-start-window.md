- 日期：2026-10-26
- 相关：[Windows 上手流程](2026-10-26-windows-onboarding.md) 第 3、4、8 节，#559

- 代码：新的 `app/src/start/`（`start.html`、`start.css`、`start.js`、`whale.js`、`text.mjs`）、`app/src/start-window.mjs`、`app/src/start-frame.mjs`、`app/scripts/start-assets.mjs`；`app/src/main.mjs`、`preload.cjs`、`window-frame.mjs`

## 为什么

- 引擎第一次启动要 3 到 20 秒，以后要 3 到 12 秒。第 3 节定了这段时间显示什么（真实阶段、说明、卡片、恢复页），没定它怎么动。
- 主 Bot 的鲸鱼是 DS Bot 自己生成的形象，用户进团队后第一眼看到的也是它。启动时让它替用户「干活」，用户进门前就认识了它，也先见过它的状态动作。
- 等待只取这些原则：
  - 有事做、有解释的等待显得短（Maister）。
  - 看得见真实的工作更让人放心，假进度适得其反（Buell 和 Norton；Harrison 等）。
  - 1 秒内不显示进度；超过 10 秒，要看得见进度和出路（NN/g）。
  - 入场不超过 1 秒，不为动画推迟启动（Android 启动画面）。
  - 天天看的画面动得越少越好（Kowalski）。
- 启动页是本地文件，引擎的页面在 `http://127.0.0.1`，两者跨源。同一个窗口里 `loadURL` 时，Chromium 不保留旧画面，也做不了跨文档过渡；不改 DSH 就接不上。窗口会先空一下，再露出 DSH 自己的加载过程，「打开团队」这一步用户其实看不到。
- 所以启动页放进单独的小窗口，团队界面在隐藏的主窗口里加载，挂载好了才露面。小窗口一直有 Mica，交接时没有空白帧。

## 已定的行为

### 1. 两个窗口（待定）

- 每次启动先出来**启动窗口**：
  - 内容区 720 × 540；显示器工作区不到 588 高时为 720 × 500。
  - 不能缩放、最大化和全屏，只有最小化和关闭两个系统按钮。
  - 无边框，40 px 的标题带可以拖动，里面什么都不放。
  - Windows 11 22H2 及以后用 Mica。
  - 在光标所在的显示器上居中。
- 启动窗口从不改大小。首次启动、以后的启动、卡片、失败页都在这一个尺寸里。
- **主窗口**照旧 1320 × 860：
  - 启动窗口第一次画好以后，主窗口隐藏着建好。
  - 引擎起来后，在里面加载引擎的本机地址（同一个地址和端口）。例外：导入卡开着、用户还没回答时不加载（插件一收到 `state` 就会建出空白团队），等回答以后、〔复制过来〕的第一段复制完以后才加载。
  - `dsBotApp.ready()` 之后才显示，启动窗口随后关掉。
- 交接前关掉启动窗口（× 或 Alt+F4）就退出应用，走现在的退出流程：停引擎，正在复制的就停下。
- 交接前再双击图标，恢复并聚焦启动窗口；交接后聚焦主窗口。
- 首次启动的选择框和提示都挂在启动窗口上。选择框从不自己弹出，只在用户点了选文件夹的按钮或链接之后出现。
- 换位置时（〔移到…〕，今天的 `notePage(t.moving)`），主窗口先隐藏，启动窗口按「以后的启动」的样子显示「正在搬 DeepSeek Bot 的数据…」（同一个卷上只是改名，这一页一闪而过）。任务栏进度照旧，搬完照旧重开；工作文件在重开后由应用后台复制，不经过启动窗口。

| 提示行 | y 220–248，居中 | 10 秒、45 秒的提示和〔打开日志文件夹〕 |

  - 没有标题行、三站、说明和底注。

### 3. 鲸鱼的总规则

- 只为真实的事动：阶段开始和完成、出卡片、失败、就绪，以及用户的指针和点击。
- 鲸鱼面朝右。主进程报告一个阶段完成时，它向右游到下一站：不会提前，也从不往回游。
- 等用户回答时静止。等得越久动得越慢，从不变快。
- 换动作时从当前姿势接着走：读出当前的 `transform`，停掉循环，再用弹簧走到下一个动作的起点。不跳回原位。
- 一个阶段等满 250 ms 才显示「进行中」；更快完成的阶段直接打勾。
- 循环状态出现后至少停 400 ms；失败和交接不等。
- 游动排队：前一段游完才游下一段，排着的那段不再下蹲。排队不会让交接晚超过 600 ms。
- 大动作只放在 SVG 外面的 HTML 包层上，用 `translate`、`rotate`、`scale`、`transform`，交给合成线程。SVG 里只动眼睛和尾巴。
- 循环用 CSS 动画，按 `html` 上的状态属性选。一次性动作用 WAAPI，结束时 `commitStyles()` 再 `cancel()`。
- 每段一次性动作带序号，新状态到了就丢掉旧的。等动画结束的地方都配一个计时器兜底，因为最小化的窗口不走动画。
- 弹簧只用 `motion.js` 的常量。头像动作的关键帧沿用插件的写法（`styles.js` 的 `bt-hop`、`bt-bob` 等），换算成像素。

| 时刻 | 鲸鱼 | 时长和曲线 |
|---|---|---|
| 首次启动入场 | 从水线下浮上来，12° 的倾斜回正；尾巴甩一下；睁眼 | `SPRING_STRETCH` 560 ms；睁眼 160 ms |
| 准备数据文件夹 | 搜索：前倾探头，眼睛左右扫 | 1 s；眼睛 1.6 s |
| 一个阶段完成 | 下蹲 120 ms，向右滑 192 px，尾巴划两下，眼睛晚 80 ms 跟上；身后的标记弹出对勾；到站点一下头 | `SPRING_SHAPE` 420 ms；对勾 `SPRING_POP` |
| 启动本机引擎 | 工作：上下晃、尾巴摆、眨眼 | 1.6 s、1.1 s、2.4 s；52.8 s 内不完全重复 |
| 10 秒 | 看向用户 600 ms，慢眨一次眼；所有循环放慢到 0.85 倍 | — |
| 45 秒 | 换成思考：歪头慢慢起伏、眯眼；尾巴停下 | 2.2 s；换动作用 `SPRING_SHAPE` |
| 打开团队 | 发消息：向前冲，每冲一次尾巴划两下 | 1.1 s |
| 应用主动问（卡片、180 秒） | 跳两下，然后静止，看着卡片 | 1.3 s × 2 |
| 用户自己引出的卡片 | 不跳，静止 | — |
| 失败 | 从当前姿势下沉 4 px、低头 4°，眼皮变重，然后完全静止 | `SPRING_SHAPE` |
| 就绪（首次启动，或重试后第一次成功） | 压扁再拉长，「^ ^」眼；拉到最长时潜下水线 | 460 ms 加 `SPRING_SHAPE` |
| 就绪（以后的启动） | 直接潜下去 | `SPRING_TAP` 290 ms |

- 动画三档用团队里设的那一档：主窗口的页面报告给应用，应用记在自己的 userData 里，下次启动时用。没有记录时（首次启动）按「正常」。
  - 安静：只有上表的状态动作。没有眼睛跟随、点击转圈、抚摸、尾巴、点头、看向用户、涟漪和「^ ^」眼。
  - 正常：加上眼睛跟随指针、尾巴、点头、看向用户、涟漪、「^ ^」眼。首次启动等待时，点鲸鱼它会转一圈；等用户回答时可以抚摸（UI 标准 8.5）。
  - 活泼：再加上等用户回答时一直跳（8.4）。
- 涟漪是一个 56 × 12 的细线椭圆，只在首次启动出现两次：浮上来和潜下去的地方。以后的启动没有涟漪。
- 鲸鱼对读屏隐藏（`aria-hidden`）。进度由三站的文字、`aria-current="step"` 和礼貌朗读区说出来：「{阶段}：进行中」「{阶段}：已完成」。

### 4. 首次启动，逐拍

时间从页面拿到 `?start=first` 的那一帧算起。

1. 入场：
   - 0 ms，鲸鱼在第 1 站从水线下浮上来。
   - 120 ms，涟漪。
   - 160 ms，标题淡入。
   - 220 / 270 / 320 ms，三站从左到右淡入。
   - 360 ms，睁眼。
   - 420 ms，底注淡入。
   - 560 ms，到位。
   入场全是 CSS，不等脚本。入场时来的卡片和就绪，等它到位再处理。
2. 到 560 ms「准备数据文件夹」还没完成、并且已经等了 250 ms，第 1 站才显示进行中，鲸鱼搜索。已经完成的话，直接游到第 2 站。
3. 600 ms 起，说明逐段出现：
   - 每段用 `bt-veil-in`，.22 s，段与段隔 0.8 s。
   - 每段从第一帧起就排在最终位置，只是透明度为 0。出现时旁边什么都不动。
   - 交接时还没出现的段落，不再出现。
   - 各段的文字：
     - 「DeepSeek Bot 是一支替你干活的 Bot 团队：你告诉主 Bot 要做什么，它安排其他 Bot 一起完成。」（14/22，`--bt-ink`）
     - 没有要导入的团队、数据文件夹里也没有团队时：「下一步：接上一个模型。推荐用 DeepSeek 账号登录（没有账号可以用手机号注册），也可以粘贴 DeepSeek API Key。DeepSeek 按用量收费。」（14/22，`--bt-ink-2`）。要导入时，这一段从第一帧起就不占位置。
     - 「聊天和设置保存在这台电脑上（对话内容会发给你选的模型服务）。」（13/18，`--bt-ink-2`）
     - 「数据保存在 `C:\Users\<用户名>\.ds-bot`，Bot 默认在 `C:\Users\<用户名>\DeepSeek Bot` 里工作。都可以在 设置 → 通用 → 位置 里改。」（13/18，路径用等宽字体）
     - 第 3 站开始、而且 DSH 会挂出「预览版说明」时：「接下来会先显示 DeepSeek Harness 的「预览版说明」。DeepSeek Bot 建在 DeepSeek Harness 上，点「继续」就行。」（14/22，`--bt-ink`）
4. 「启动本机引擎」：鲸鱼在第 2 站工作。5 秒起，标题行右边显示「已用 N 秒」，每秒改一次，数字不滚动。没有百分比。
5. 10 秒：提示行出现「第一次启动会慢一些，Windows 可能在检查刚装好的文件。」鲸鱼看向用户一次，循环放慢。第 2 站完成时，这行字淡出。
6. 45 秒：提示换成「比平时慢，可能是杀毒软件在检查新文件，请再等一会儿。」，90 ms 后行尾出现 28 px 的〔打开日志文件夹〕。鲸鱼改成思考。
7. 180 秒：见第 6 节。
8. 引擎起来：主进程在隐藏的主窗口里加载引擎的页面，开始 20 秒的就绪检查。鲸鱼游到第 3 站，改成发消息。导入卡开着、还没回答时只给第 2 站打勾：不加载页面、不游到第 3 站、不开始 20 秒检查，三件事都等回答以后（〔复制过来〕的等第一段复制完）。
9. `dsBotApp.ready()`：见第 8 节。

- 卡片等用户回答时，已用秒数暂停并隐藏，回答后接着走。10 秒、45 秒和 180 秒都按这个时钟算：用户自己想了多久，不算在引擎头上。

### 5. 以后的启动

- 0 ms：64 px 的鲸鱼在窗口中间浮上来（`SPRING_TAP` 290 ms），不倾斜，眼睛睁着，没有涟漪。60 ms 后，「正在打开你的团队…」淡入。
- 前 1 秒什么都不再动。1 秒后鲸鱼开始工作（只上下晃和眨眼），那行字带流光。
- 10 秒起，下面显示「已用 N 秒」。
- 45 秒：「比平时慢，请再等一会儿。」〔打开日志文件夹〕。
- 180 秒：和首次启动一样。
- 就绪时没有庆祝：字淡出 .16 s，鲸鱼从当前姿势潜下去；120 ms 后主窗口显示。
- `DS_BOT_HOME` 的一次性运行用这一套，只是不出卡片。

### 6. 卡片、180 秒和导入

- 所有卡片用同一套变形：
  - 出现：说明淡出 .16 s；卡片的底色和边线两层从 0 高长到内容的高度（`clip-path`，走 `SPRING_SHAPE`；底色 .22 s 淡入）；内容先按最终尺寸排好，晚 70 ms 淡入；焦点移到主按钮。
  - 回答后：内容 .16 s 退场（下沉 6 px、缩到 .975、模糊 3px），卡片收回，说明晚 70 ms 回来。
  - 以后的启动：整组先上移，卡片再出现。
- 卡片等用户时，进行中的那一站停掉流光，阶段名保持 `--bt-ink`。
- 鲸鱼跳不跳：
  - 应用主动问的卡片（推荐盘、找不到数据文件夹、导入、180 秒），跳两下再静止，看着卡片。
  - 用户自己引出的卡片（「其他位置…」选完后的「会放在…」、停止复制的确认），不跳。
  - 同一件事又出了新问题（复制时空间不够），跳一下。
- 选位置的卡片只有推荐盘这一种，只在首次启动出现，〔放到 D 盘〕〔仍然放在 C 盘〕都已经试写通过（上手流程第 3 节）；以后的启动还会出「找不到数据文件夹」卡：
  - 推荐盘：「C 盘只剩 1.2 GB。放到 D 盘（剩 412 GB）？」〔放到 D 盘〕（主按钮，拿到焦点）〔仍然放在 C 盘〕，按钮行末尾一个小链接「其他位置…」。默认位置不能用时，第一句换成原因（「DeepSeek Bot 没有权限在 `C:\Users\<用户名>` 里写文件。」），第二句一样；按钮只有〔放到 D 盘〕（主按钮）和小链接「其他位置…」，没有〔仍然放在 C 盘〕；没有可推荐的盘时只有〔选择其他位置…〕。
  - 「其他位置…」打开系统选择框，卡片留在后面。定出的根就是用户选的文件夹时（上手流程第 3 节的规则），卡片直接收回，照常启动，不确认。应用在里面加了一层 `DeepSeek Bot` 时，同一张卡变形成「会放在 `D:\DeepSeek Bot`」〔继续〕（主按钮）〔重新选〕。选的位置不能用，同一张卡写一句原因（「DeepSeek Bot 没有权限在 `D:\Data` 里写文件。」「`C:\Users\<用户名>\OneDrive\文档` 在 OneDrive 里，同步会打断正在写入的聊天记录。」「`D:\Projects\DeepSeek Bot` 里已经有别的文件。」），〔重新选〕（主按钮），来时那张卡的〔放到 D 盘〕〔仍然放在 C 盘〕照旧留着；选择框被取消就回到来时的卡。「会放在…」和被拒绝的卡也有脚注。
  - 脚注都是「以后可以在 设置 → 通用 → 位置 里改。」
  - 没有更好的盘时不出卡片：提示行写「C 盘只剩 1.2 GB」，10 秒的提示来时换掉它。
- 重装（`C:\Users\<用户名>\.ds-bot` 里有团队、没有保存的位置）不出卡片，盘不够也不出：说明的小字改写成「接着用上次的数据：6 个 Bot、2 个群聊（`C:\Users\<用户名>\.ds-bot`）。可以在 设置 → 通用 → 位置 里改。」，「下一步：接上一个模型…」那一段不显示。
- 180 秒：「启动比平常慢很多。可以再等一会儿，或者重试。」〔继续等待〕（主按钮）〔重试〕〔打开日志文件夹〕
  - 〔继续等待〕：卡片收回，180 秒后再问。
  - 〔重试〕：重启引擎，时钟从 0 开始，鲸鱼抖一抖，回到工作。
  - 卡片还在时引擎起来了：卡片收回，照常游到第 3 站。
- 找不到数据文件夹（多见于以后的启动）：文字和按钮按第 3 节已定的，主按钮在前。〔重试〕后还是找不到：按钮下面出现「还是找不到这个文件夹。」（`--bt-danger`，4 秒后淡出）。鲸鱼的眼睛左右看一遍，不跳。
- 导入（第 4 节）都在纸面里，用同一套变形：
  - 导入卡一句话：「DeepSeek Harness 里有 6 个 Bot 和 2 个群聊（对话 1.2 GB，工作文件 3.4 GB）。复制过来？」，下面一行小字「复制后会多占 4.6 GB，DeepSeek Harness 里的原件不动。」，〔复制过来〕（主按钮，拿到焦点）〔先不复制〕，脚注「也可以在 设置 → 通用 → 位置 里复制。」「详细」是和失败页一样的折叠区：找到的名字和段数、会复制什么、「模型设置：DeepSeek API · DeepSeek-V4-Pro　更换」、两个勾选框；展开时卡片的边用 `SPRING_SHAPE` 长高，内容晚 70 ms 淡入。
  - 卡片一出现，第 2 站就开始预热，没被 DSH 占着时检查对话同时进行，鲸鱼在第 2 站跳两下后静止；预热好了也只给第 2 站打勾，不游到第 3 站。答〔先不复制〕时鲸鱼点一下头，预热好的引擎接着当正式引擎用，不重启。
  - 空间不够（只查第一段）：「空间不够：复制要约 1.7 GB，C 盘只剩 1.5 GB，还差 0.2 GB。」〔选择其他位置…〕（主按钮）〔先不复制〕
  - 复制中：
    - 卡片标题「正在复制 Bot 团队…」，三步用和三站一样的标记和对勾，竖着排：「检查对话 23/143」→「复制 Bot 和对话 820 MB / 1.2 GB」→「启动团队」。
    - 当前一步下面是 4 px 的真实进度条（`scaleX`，`SPRING_LIST`），不往回走。
    - 剩余时间按整分钟写：「还要大约 2 分钟」「不到 1 分钟」。变动满一分钟才改，不倒数到 0。
    - 任务栏进度显示在启动窗口上。
    - 鲸鱼工作，每完成一步点一下头。
  - 停止复制：确认在卡片里就地展开：「停下后不会留下复制了一半的团队，DeepSeek Harness 里的团队不受影响。」〔继续复制〕（主按钮）〔停止复制〕（危险色文字）。鲸鱼静止。
  - DSH 正在用这个团队（答〔复制过来〕后）：鲸鱼静止，不晃。每 2 秒重查一次，不显示任何东西；锁一放开，卡片直接变成复制中。卡上一个〔先不复制〕（主按钮）。「正在下载」的卡也有〔先不复制〕（主按钮），加「下载太慢？手动下载」；下载失败时〔重试〕〔手动下载〕。
  - 复制失败：鲸鱼用失败的姿势。
  - 工作文件不经过启动窗口：团队打开后由应用在后台复制，进度在 设置 → 通用 → 位置 和 Main Bot 聊天里的「复制好了」卡上。

### 7. 失败、更新和界面没加载出来

- 失败后 1 秒内：
  - 标题换成「DeepSeek Bot 没能启动」。
  - 失败的那一站换成危险色的叉，停掉流光。
  - 已用秒数和提示行淡出。
  - 纸面变成恢复卡：一句原因、五个按钮、「详细信息」。
  - 焦点移到〔重试〕。窗口不隐藏。
- 〔复制详细信息〕点过后，按钮上的字变成「已复制」，1.6 秒后变回来。「详细信息」最多展开 168 px，日志在框里滚动。
- 有新版本时：
  - 恢复卡在原因和按钮之间展开一条更新条。〔下载并安装〕成为唯一的主按钮，〔重试〕变成普通按钮。
  - 下载中显示「正在下载 {版本}（37%，78/212 MB）」、4 px 的进度条和「下载太慢？手动下载」。
  - 下载完显示「正在安装，装好后会重新打开。」
  - 下载失败显示「下载失败。」〔重试〕〔手动下载〕。
  - 鲸鱼抬一次头，看向更新条，然后又静止。
- 恢复卡上的选择：
  - 〔重试〕：已完成的站保持完成，失败的那一站回到进行中，鲸鱼抖一抖，回到工作。
  - 〔换个位置…〕和〔用新的空白团队开始…〕：先选文件夹（定根和首次启动同一条规则）；然后鲸鱼沉到水线下，三站一起淡回未开始，鲸鱼在第 1 站重新浮上来。
  - 重新开始的这一轮成功时，照首次启动庆祝一次；以后的启动也一样。
- 团队界面 20 秒没加载出来：
  - 主窗口始终不显示。
  - 第 3 站换成危险色的叉，标题换成「团队界面没有加载出来。」，卡片里是〔重新载入〕〔打开日志文件夹〕〔复制详细信息〕。
  - 〔重新载入〕：在隐藏的主窗口里重新载入，回到第 3 站，20 秒重新算。
  - `ready()` 晚到了也直接交接，不庆祝。

### 8. 交接

首次启动，以及重试后第一次成功。`t0` 是 `ready()` 到达后、鲸鱼停在第 3 站的那一刻：

| 时间 | 启动窗口 | 主进程 |
|---|---|---|
| 0 | 第 3 站弹出对勾；「^ ^」眼；开始压扁 | — |
| 160 ms | 已用秒数和提示行淡出 | — |
| 460 ms | 拉到最长时潜下水线；标题、三站、纸面、底注淡出 .16 s | — |
| 560 ms | 涟漪 | — |
| 620 ms | 发 `handoffShow` | 启动窗口离开任务栏；主窗口以启动窗口的中心居中（不超出工作区），显示在启动窗口上面 |
| 880 ms | 潜完，发 `handoffDone` | 主窗口显示满 250 ms 后关掉启动窗口，最晚 400 ms |

- 以后的启动：字淡出 .16 s，鲸鱼 290 ms 潜下去；120 ms 时发 `handoffShow`，290 ms 时发 `handoffDone`。
- 页面没发 `handoffShow` 时，主进程自己显示主窗口：首次启动在 1.5 秒后，以后的启动在 0.8 秒后。
- 启动窗口有焦点时，主窗口直接显示并拿到焦点。
- 启动窗口没有焦点时，主窗口不抢焦点，放在启动窗口原来的层次上，任务栏按钮闪烁。
- 启动窗口最小化着时，主窗口也最小化着出现，任务栏按钮闪烁。
- 主窗口第一次露面时，DSH 的加载、第一次挂载侧栏（#559）都已经做完，「预览版说明」已经显示出来。
- 两个窗口各用各的颜色：启动窗口是 DeepSeek 主题的浅色或深色，主窗口是用户自己的主题。

### 9. 减少动态效果

- 跟随 `prefers-reduced-motion`（Windows 上是 设置 → 辅助功能 → 视觉效果 → 动画效果）。窗口开着时切换，也立刻生效：正在跑的动画直接到终点。
- 鲸鱼一直是静止的画面：没有浮上来、游动、循环、跳、涟漪、尾巴、跟随和抚摸。换站时淡出 .12 s，换到新的一站，再淡入 .12 s。
- 状态只靠眼睛直接切换：平时睁眼，45 秒起眯眼，就绪时显示「^ ^」600 ms，失败时眼皮变重。
- 对勾、卡片、提示行和更新条只淡入 .12 s、淡出 .16 s，没有模糊、位移和缩放。卡片高度直接到位（内容先是透明的）；以后的启动整组上移也直接到位；没有流光。
- 交接只淡出 .12 s，然后显示主窗口。
- 信息一样不少：已用秒数照常走，三站的文字、提示行、按钮和朗读都在。

### 10. 颜色、Mica 和标题带

- 颜色是 UI 标准 2.1 节的 DeepSeek 主题，浅色、深色各一套，定义在 `start.css` 的 `:root` 上。由 `start-assets.mjs` 从 `themes.js` 和 `inks.js` 生成，用 `--check` 对照。鲸鱼用 `--bt-ink-deepseek`（`#4D6BFE` / `#6A84FF`）。
- 浅色还是深色看 `nativeTheme.themeSource`：
  - 主进程把团队界面最后一次报告的值和动画档，记在 userData 的 `start-frame.json` 里，建启动窗口之前先设好。
  - 没有记录时跟随系统。
  - 不写 `DSH_HOME` 和 `~/.dsh`。
- Windows 11 22H2 及以后：
  - 窗口用 `backgroundMaterial: 'mica'`，背景 `#00000000`；页面的 `html`、`body` 透明。
  - 系统按钮颜色 `#00000000`，符号用 `--bt-ink`，按钮下面也是 Mica。
  - Mica 上最浅的字用 `--bt-ink-2`，不用 `--bt-ink-3`。
- 其他 Windows：窗口背景和系统按钮颜色都用 `--bt-main`。页面照样透明，自己不用分辨是哪种情况。
- 一屏最多两处大面积强调色：鲸鱼和唯一的主按钮。
- 没有警告色（`--bt-warn` 未定）：空间不足、OneDrive 和慢的提示都用中性墨色。
- 字体：`-apple-system, BlinkMacSystemFont, "Segoe UI", "Microsoft YaHei UI", system-ui, sans-serif`；路径和日志用 `ui-monospace, Consolas, monospace`。字号只有 13/18、14/22、15/20（600），数字用等宽数字。
- macOS 和 Linux：系统标题栏，没有标题带，其余一样。

### 11. 实现

- `main.mjs` 启动时的顺序：
  1. `setMenu`。
  2. 读 `start-frame.json`，设 `themeSource`。
  3. `hostPort()`，挪到建窗口之前。
  4. 建启动窗口（`show: true`），`loadFile`。
  5. 动态导入其余模块。
  6. 位置检查（结果变成卡片）。
  7. 启动引擎。
  启动窗口画好后，再建隐藏的主窗口。
- 启动页的文件：
  - `start.html`：CSP `default-src 'self'; base-uri 'none'; object-src 'none'`，没有内联样式和脚本。
  - `start.css`。
  - `start.js`：桥和界面。
  - `whale.js`：鲸鱼的状态机。
  - `text.mjs`：中英文，主进程也用。
- 所有状态的 DOM 一开始就在页面里，用 `hidden` 和属性切换，运行时不插入大块节点。
- 鲸鱼的 SVG 由 `start-assets.mjs` 从 `characterMarkup('whale', 'deepseek')` 生成后写进 `start.html`，遮罩 id 固定。同一个脚本把 `motion.js` 的弹簧和主题色写进 `start.css`。`npm test` 跑它的 `--check`。
- 预载只在页面地址正好是启动页时暴露 `dsBotStart`（`onState`、`act`）。
- 主进程每次都发完整的状态，页面重新载入后再发一次。预载记住最后一份，有人订阅时先补发。
- 主进程只接受来自启动窗口主框架、地址完全相同的 `act`，而且名字要在白名单里。
- 主进程管：阶段、180 秒和 20 秒两个计时器、交接的兜底计时器、任务栏进度、更新状态。页面按时钟算 5 秒、10 秒和 45 秒。
- `main.log` 记三个阶段各用了多久。
- 启动窗口在交接时销毁，它的渲染进程一起退出。

## 不做什么

- 不画百分比进度条：引擎不报百分比。复制和下载的进度条用真实的字节数。
- 不编造阶段，不为动画推迟启动。庆祝只在首次启动和重试后第一次成功时有，主窗口在 `ready()` 后约 620 ms 露面。
- 不放轮播的提示和笑话。鲸鱼不说话、不冒气泡、不挡卡片和按钮，也不要用户做什么。失败时不哭不闹。
- 鲸鱼没有「?」徽标（UI 标准 8.2：大头像不显示徽标），不侧身跃出水面，不喷水。
- 不画 DSH 的鲸鱼标志，不用其他产品的动画、插图、声音和字体。
- 不往引擎的页面里注入 CSS 或 DOM 来接画面，不改 DSH。
- 不用 Rive、Lottie 和网络字体：CSP `default-src 'self'` 不允许 WASM，也不另加运行时。
- 标题带里不放能点、能抚摸的东西。

## 已知限制

- 主窗口在隐藏时启动 DSH 和 ds-bot。`dsBotApp.ready()`、#559 的重新挂载检查和系统按钮颜色的测量，都在看不见的窗口里跑，要在 M4 验证。
- 从没显示过的 Mica 窗口第一次 `show()` 时，可能先露出一两帧空的 Mica。M4 用 60 帧录像检查；有的话，改成先把主窗口放在启动窗口下面，启动窗口潜完再关。
- `#00000000` 的系统按钮颜色，只在一台 Windows 11（26200，深色，窗口不在前台）上验证过是透明的。前台、浅色、悬停和按下都没验证。按钮画成不透明的系统，改用不透明的 `--bt-main` 窗口。
- 未打包、机器忙时实测：进程启动后 1.35–1.57 秒窗口才建好，页面第一次画出来还要再等 0.9–1.0 秒。启动页的第一帧和空窗口一模一样，这段看不出来，但入场会晚。
- SVG 里的尾巴和眼睛、内容的模糊淡入和流光不走合成线程。杀毒软件在扫描、引擎又在启动时，可能卡顿；那时先去掉尾巴。
- 动画档和浅深色要等团队界面报告一次才记得住。在应用外改过主题时，下次启动先用旧的。
- 第 2 站结束是从引擎的 HTTP 起来推断的：DSH 不报命名的阶段（「需要 DSH 提供的」第 11 条）。
- 工作区不到 588 高的显示器上，窗口只有 500 高，说明和长卡片要在纸面里滚动。
- 启动时多一个渲染进程（约 40–60 MB），交接后销毁。
- 交接的 250–400 ms 里两个窗口同时存在。启动窗口已经不在任务栏，但 Alt+Tab 里可能短暂看到两个。
