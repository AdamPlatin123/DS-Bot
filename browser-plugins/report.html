决定 Agent 项目 DSH 插件 三个插件 实测

已经定下来的

维护者确认：以前写「Bot 不操作浏览器」，是等这次做。全团队只挂一个浏览器后端，不让这个 Bot 用 refs、那个 Bot 用 script。每个 Bot 仍有自己的浏览器，cookie 不在 Bot 之间同步。群聊各用各的，也就是用各自 Bot 的那份 profile。

同一个 Bot 的私聊、它加入的群、以及换段之前的会话，打开同一份目录 bot/browser-profiles/<botId>/，所以换段之后登录还在。这是相对 DSH 官方 browser-use 的差别：官方的浏览器属于那一个活着的 Session，换段就丢掉登录。

登录、付款、验证码交给用户（browser_handoff / browser_resume）。没有另加域名黑名单。默认不打开插件，桌面里的只读 read_browser 不变。这个分支不合进 dev。

为什么 cookie 不同步

你说浏览器保持独立、别串，同步 cookie 就是串。一个 Bot 读到网页里的指令，不该因此拿到另一个 Bot 已经登入的站。两个 Bot 要同一个登录时，各自登一次。以后若要复制，做成一次显式动作，不在后台同步。

和桌面面板的关系

现在的面板是 Electron webview，Bot 只能读。这三个插件驱动的是 Playwright 的 Chromium。两边不自动对齐 cookie。用户暂时不能在面板里看着 Bot 点击。要把它们合成一个窗口，是下一步，不是这次。

Agent 浏览器项目

下面七个都对过 DSH 的 Session 模型和 DS Bot 的长期身份。Chrome DevTools 按你的判断留在调研里，不做成插件。ego lite 这台 Linux 环境跑不了，用 script 插件测它那种「一段脚本」的形状，不把它算成测过。

browser-use

开源 Python / TypeScript agent，另有 Cloud。CLI 3.0 把一整段浏览收成一次 browser_exec。和 Bot 的差距：它自己就是 agent，登录跟它的浏览器走，不跟 DS Bot 的身份走。官方 DSH 只登记一个 provider，换 Session 不恢复 profile。

Playwright MCP

微软的无障碍树和编号。DSH 官方 provider 之一。逐步、可核对，适合多模态模型看截图、也适合只看文本。官方挂载按 Session 收浏览器。我们的 refs 用同一类操作，但 profile 按 Bot 留在磁盘上。

Stagehand

Browserbase 的 act / extract / observe，里面还会再调一个模型。DSH 有 native provider，文档写明这个内层模型还没接上 DSH 的路由和用量。Bot 的记忆里看不到内层怎么点的。适合当对照，不适合当团队唯一后端。

Skyvern

偏视觉和流程的开源浏览器 agent，强项是表格和长表单。它自带一套 agent 循环和部署。接到 Bot 上会变成第二个循环。这次没有把它的服务拉起来测，结论来自它的产品形状。

ego lite

Citro 的浏览器，人和 agent 各有 Space，ego-browser 用一段 Node 脚本驱动真 Chromium。DSH 上有 dsh-ego-browser（回忆、执行、学会、把键盘交还）。官方支持 macOS。这台机器测不了，handoff 的做法吸收进了三个插件。

Hermes

Nous Research 的 agent。默认浏览器模式是 Browser Use CLI 的 browser_exec，可以套本地 Chromium、Cloud、Browserbase、Lightpanda。他们在 PR #81958 里报过多步网页任务上 token 少了大约一半，准确率持平。那是他们的数字，不是这次测的。script 插件是这个形状，再加上每 Bot 一份 profile。

OpenCode v2

桌面版有 browser 命名空间：先拿到 tabID，再快照、点击、截图、看网络。另有 opencode-chromium，四个工具，setup --targets dsh 能写进 DSH 的 MCP。标签属于会话，不按 Bot 留登录。Chrome DevTools MCP 也看过：工具面是调试器，你说不好用，不进可选后端。

为 Bot 做的三个插件

refs

browser_open browser_snapshot browser_click browser_fill browser_screenshot browser_handoff。编号在快照里，页面一变就作废。开放 Shadow DOM 和同源 iframe 的文字会写进快照。每一步都在会话里。

script

browser_exec 跑一段已经注入帮手的 JavaScript，用 done(answer) 交卷。对应 Hermes / ego 的一段脚本。失败了可以再交一段。登录仍走 handoff。

task

browser_task 收一个目标，内部用 refs 的工具和同一次模型调用跑完，结果里带步骤清单。Bot 的对话里只有一次工具调用。适合整段网页差事，不适合要中途改口的活。

三个包在 browser-plugins/refs、script、task，都有 apply，可以单独装进 DSH。单独装时目录按 Session id，不按 Bot。DS Bot 挂载时才换成 Bot id。团队配置只接受一个名字。
